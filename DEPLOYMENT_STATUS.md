## What works

Full end-to-end regulatory workflow, verified against a live database:

0. **Public landing page** at `/` explaining the platform, with sign-in/register entry points.
1. **Authentication** — register, login, JWT session, logout, profile update.
2. **Applications** — create, search, filter, paginate, view detail, submit for review.
3. **Documents** — upload (PDF/PNG/JPEG), SHA-256 fingerprinting, duplicate detection, delete while draft.
4. **Document authentication** — recompute SHA-256 and compare with the recorded fingerprint (tamper detection).
5. **Compliance** — seeded statutory rule set, on-demand rule evaluation, findings with dispositions (accept/resolve/reject).
6. **Evidence requests** — reviewers request additional evidence, applicants respond.
7. **Audit trail** — immutable event log for every significant action.
8. **Reports** — portfolio summary, status/category distributions, monthly volume, approval rate.
9. **Notifications** — derived from evidence requests, findings and decisions.
10. **Role-based access** — applicant / reviewer / admin scoping on every endpoint.

| `ADMIN_PASSWORD` | set in the Render dashboard (secret) |
| `ENVIRONMENT` | `production` |

### Vercel (frontend)

| Key | Value |
| --- | --- |
| `VITE_API_BASE_URL` | *(optional)* leave unset to use the same-origin proxy in `frontend/vercel.json` |

`frontend/vercel.json` proxies `/api/*` and `/uploads/*` to the Render backend, so the
frontend works even if `VITE_API_BASE_URL` is not configured. It also rewrites all other
paths to `index.html` so deep links (e.g. `/applications/<id>`) survive a page refresh.

## Database behaviour

The backend **prefers PostgreSQL** and **falls back to SQLite** automatically:

- If `DATABASE_URL` is set and reachable, it is used (persistent storage).
- If `DATABASE_URL` is missing or unreachable, the service starts on a local SQLite
  file (`backend/verisure.db`) so the application always works. A prominent error is
  logged, and `/api/health/db` reports `is_fallback: true` plus the connection error.
- SQLite data does **not** survive a redeploy. Set `DATABASE_URL` for persistence.

Column types are dialect-agnostic (`CoercingUuid`), so the same models run on both.

### Diagnosing the database

```
GET https://verisure-backend-m1rb.onrender.com/api/health/db
```

Returns the active backend, whether it is a fallback, table count and the last
connection error (credentials are never exposed). If `is_fallback` is `true`, the
Render `DATABASE_URL` needs fixing.

## Schema creation

The `alembic/versions/` folder has no revision files, so `alembic upgrade head` is a no-op.
The schema is created in two ways:

1. `backend/create_tables.py` — run locally with `DATABASE_URL` set to create all tables.
2. **Startup safety net** in `backend/app/main.py` — `Base.metadata.create_all()` runs on
   every boot, so a fresh database self-provisions. The same startup hook seeds the default
   compliance rules and the administrator account.

## Known limitations (free-tier constraints)

- **Ephemeral uploads** — Render's filesystem is not persistent. Files may disappear on
  restart/redeploy. The SHA-256 fingerprint stays in the database, and the UI clearly reports
  "file unavailable" instead of a false verification failure.
- **Cold starts** — the Render free instance sleeps after inactivity; the first request may
  take ~30–50 seconds.
- **No OCR** — Tesseract is not available on the free tier, so no text extraction or
  auto-classification of scanned documents.
- **No email delivery** — SMTP is unconfigured; notifications are in-app only.
- **Local preferences** — the Settings toggles are stored in `localStorage`, not the server.

## Local development

```powershell
# Backend
cd backend
python -m venv venv
.\venv\Scripts\pip install -r requirements.txt
$env:DATABASE_URL="postgresql://user:pass@host/db?sslmode=require"
$env:ADMIN_PASSWORD="change-this-password"
.\venv\Scripts\python -m uvicorn app.main:app --reload --port 8000

# Frontend (second terminal)
cd frontend
npm install
$env:VITE_API_BASE_URL="http://127.0.0.1:8000"
npm run dev
```

Then run the test suites:

```powershell
cd backend
$env:DATABASE_URL="postgresql://..."
.\venv\Scripts\python smoke_test.py
.\venv\Scripts\python live_test.py
```
